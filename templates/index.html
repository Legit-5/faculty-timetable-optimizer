📘 College Viva & Algorithm Architecture Guide

🧠 1. AI Algorithm: Greedy Algorithm with Heuristic Scoring

This system utilizes an Informed Search (Greedy Heuristic) Algorithm. At every available (Day, Time Slot), the engine examines all valid subject-faculty candidates and assigns the candidate with the lowest heuristic score.

Heuristic Evaluation Function:
Score = Consecutive_Penalty + Daily_Repeat_Penalty - Remaining_Hours_Bonus + Workload_Penalty + Rotation_Offset
  • Consecutive Penalty (+10,000): Prevents teaching the same subject back-to-back.
  • Daily Repeat Penalty (+250 × count): Prevents clustering the same subject on one day.
  • Remaining Hours Bonus (-60 × remaining): Prioritizes subjects with the most unscheduled hours.
  • Workload Penalty (+15 × load): Automatically balances total lectures across all teachers.

❓ 2. Is this Machine Learning? (Critical Viva Question)

No, this is NOT Machine Learning. It is a deterministic heuristic search algorithm. Machine Learning requires training datasets, weights optimization, and statistical inferences. A college timetable optimizer must guarantee 100% hard constraint satisfaction (zero double-bookings, compulsory subject mappings), which heuristic search achieves deterministically and explainably.

⚙️ 3. Step-by-Step Execution Pipeline

  1. Input Validation: Verifies unique faculty/subjects, positive hours, and non-overlapping time slots.
  2. Capacity Check: Confirms Total Required Hours ≤ Total Days × Total Slots.
  3. Candidate Filtering: Filters candidates by: (a) Subject hours > 0, (b) Faculty mapped to subject, (c) Faculty available on day, (d) Faculty not busy in slot, (e) Max daily limit ≤ 2.
  4. Greedy Selection: Calculates score for candidates & selects lowest. If no candidate exists, designates — Free Period —.
  5. State Update: Updates remaining hours, faculty total workload, and busy slot sets.
  6. Final Verification: Validates zero collisions and generates workload and hours dashboards.
