Algorithm Guide & Viva Reference

Architecture, constraints, and talking points for the Greedy Heuristic scheduling engine

🧠 Algorithm: Greedy + Heuristic

This system uses an Informed Search (Greedy Heuristic) Algorithm. At every available (Day, Time Slot), the engine examines all valid subject-faculty candidates and assigns the one with the lowest heuristic score.

Score = Consecutive_Penalty + Daily_Repeat_Penalty − Remaining_Hours_Bonus + Workload_Penalty + Rotation_Offset
Penalty Weights
  • Consecutive (+10,000): Prevents the same subject back-to-back in one day
  • Daily Repeat (+250 × count): Avoids clustering same subject on one day
  • Hours Bonus (−60 × remaining): Prioritizes subjects with most pending hours
  • Workload (+15 × load): Distributes lectures fairly across all faculty
  • Rotation Offset (+idx × 0.1): Minor tie-breaker for round-robin fairness
❓ Is This Machine Learning?
ℹ️
No — This is NOT Machine Learning
It is a deterministic heuristic search algorithm.

Machine Learning requires training datasets, weight optimization, and statistical inference. A college timetable optimizer must guarantee 100% hard constraint satisfaction (zero double-bookings, compulsory subject mappings), which heuristic search achieves deterministically and explainably.

⚙️ Execution Pipeline
  1. Input Validation: Verifies unique faculty/subjects, positive hours, non-overlapping time slots
  2. Capacity Check: Confirms Total Required Hours ≤ Total Days × Total Slots
  3. Candidate Filtering: Subject hours > 0, Faculty mapped, Available today, Not busy, Daily limit ≤ max
  4. Greedy Selection: Calculates score for each valid candidate → picks lowest score
  5. Free Period Assignment: If no valid candidate exists, slot marked as Free Period with reason
  6. State Update: Decrements remaining hours, updates workload counters, marks faculty busy
  7. Final Verification: Validates zero collisions, generates workload and hours dashboards
🔒 Hard vs Soft Constraints
Hard Constraints (strictly enforced)
  • Faculty must be mapped to the subject
  • Faculty available on the scheduled day
  • No double-booking (same faculty, same slot)
  • Subject required hours ≥ 0
  • Max daily lecture limit enforced
Soft Constraints (heuristic optimization)
  • No consecutive identical subjects
  • Minimize same subject on same day
  • Prioritize high-remaining-hours subjects
  • Balance workload across all faculty
